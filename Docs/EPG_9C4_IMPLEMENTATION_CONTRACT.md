## 目标与最高约束

9C.4 将 9C.3 的文件下载、流式解析、SQLite generation、原子发布和有限查询安全接入生产
Repository、App、直播页面与播放器。生产层只持有当前展示所需的有限 DTO，绝不回填完整
`XMLTVGuide` 或 `XMLTVScheduleIndex`。

EPG 是播放增强层。无论下载失败、SQLite busy、缓存打不开、输入损坏、查询取消、预算超限或频道
无法匹配，视频播放链路都不得等待 EPG，也不得因 EPG 错误失败。

9C.4-G 通过后直接进入 10A Full Guide/Grid EPG，不另设内容重复的 9C.5。10A 只能消费本阶段
冻结的 Now/Next、窗口和有限分页接口。

## 范围

本阶段包括生产缓存所有权、Repository 接入、XMLTV 刷新与有限查询、Xtream short EPG 的有界缓存、
直播卡片和播放器 Now/Next、来源/睡眠/退出生命周期、后台有限维护、旧缓存升级语义、真实来源、
资源门禁、全量回归与 Release 安装。

全屏节目表网格、七天浏览、录制/预约、多个 EPG 源合并、模糊频道匹配、在线频道数据库和 Xtream
全量 XMLTV 自动发现留给后续阶段。

## 身份与交付合同

所有异步展示结果携带统一 `EPGResultToken`：

- `serviceIncarnation`：生产 EPG 服务实例身份；
- `resourceIdentity`：不含凭据的稳定资源身份；
- `sourceEpoch`：来源配置/账号修订代次；
- `dataVersion`：XMLTV generation 或 Xtream 频道缓存版本；
- `demandRevision`：当前页面/播放器展示需求代次。

UI 交付前在 MainActor 的单个无悬挂点临界区一次核验完整 token。滚动只改变 `demandRevision`，不得
撤销仍合法的资源导入。服务重建、来源修改、active generation 切换和需求变化都使旧结果失去交付资格。

数据库发布资格继续使用 9C.3 的 import handle。发布资格和 UI 交付资格是两个不同层级，不能把页面
滚动传播为下载/导入取消。

## 输入与空表合同

导入来源或用户配置给出的 XMLTV 使用 9C.3 的资源级 importer。Xtream short EPG 按频道请求和缓存，
不得硬塞进“一来源一份 XMLTV”的激活语义。上层统一有限 DTO，不强迫两种输入共享错误的持久化单位。

只有以下条件全部成立才可发布合法空 generation：输入完整读至 EOF；XML/gzip 完整性通过；解析无
结构性错误；数据库写入与验证完成；发布身份仍有效；原始 `programme` 元素数量为零。

存在 `programme` 元素但全部无效、超时、取消、损坏、数据库失败或查询超预算均为失败，不能转换成
“没有节目”。某个频道或查询窗口没有结果也不能据此发布空 generation。

## 新鲜度、覆盖与重试合同

缓存事实、刷新状态和当前查询结果分别建模。失败刷新允许旧 active 继续以缓存状态显示，但不能把旧
数据重新标记为新鲜。`freshUntil`、`coverageEnd`、`nextRetryAt` 分开持久化/表达。

正常刷新候选时间为 `min(freshUntil, coverageEnd - leadTime)`，同时受最小刷新间隔、失败退避和同资源
合并约束。整体 coverage 即将结束可触发资源刷新；正在播放且已明确匹配的频道覆盖不足可限频提前刷新；
未匹配或歧义频道不能反复触发整份下载。合法空表使用独立的短重试周期。

默认策略冻结为 XMLTV 成功 TTL 六小时、Xtream short EPG 五分钟、合法空表十五分钟、明确 unsupported
一小时、失败首次至少六十秒并指数退避至十五分钟。实际 coverage 可使刷新早于 TTL。

## 有界展示与 Xtream 合同

一次 Now/Next 查询最多 100 个频道、返回有效载荷最多 2 MiB；展示层最多保留 100 个频道、估算有效
载荷最多 8 MiB。窗口查询限单频道、最长 24 小时、每页最多 500 条；不得无限累计所有分页。

进度由已取得节目的时间本地计算，节目边界由统一调度器合并重查；不允许每张卡片轮询 SQLite，也不把
高频时间变化发布到全局 AppState。

Xtream 缓存身份至少绑定 provider/account identity、server identity、configuration revision 和 streamID，
身份只存内部 ID/摘要，不存凭据。账号、服务器或认证配置改变会撤销旧请求和缓存资格。

Xtream short EPG 保留现有 HTTP 原始响应 1 MiB 上限，并同时实施单字段、单条目、缓存条目数和总计费
字节限制。计费包含所有保留字符串 UTF-8 字节、缓存键、必要元数据及每条 DTO 固定开销。解析逐条准入，
不得先构造无界数组再检查；当前不展示的 description 不保留。计费是准入预算，真实内存仍以实测为准。

## 调度、暂停、关闭与维护合同

资源刷新与展示查询分别拥有任务。可见区域变化取消旧查询，不能反复取消合法 XMLTV 下载/导入。
优先级依次为正在播放频道、实际可见频道、有限邻近预取。同资源普通刷新合并；强制刷新沿用 supersede
和排空合同。

睡眠是可恢复暂停：停止接收新工作、撤销交付资格、请求取消、有界等待后返回。超时后保留 draining
状态和资源所有者；不关闭仍在使用的数据库、不删除仍占用的暂存文件，唤醒也不能启动第二条冲突流水线。
真正 `close` 只用于服务生命周期结束；退出也有等待上限，进程终止后的残留依靠事务原子性和启动恢复。
具体 deadline 在 9C.4-A 测量协议中冻结为睡眠 750 ms、退出 2 s，并使用不及时响应取消的测试任务验证。

后台维护分批处理 `cleanupIncomplete`、retired/abandoned generation、崩溃暂存、WAL 和缓存配额；每轮
有行数及时间预算并主动让出执行时间。恢复扫描必须可推进，不能永远扫描同一目录前缀。任何维护失败
不得删除 active、未知文件或业务数据库。

## 旧缓存升级合同

旧 XMLTV JSON 不做全量解码迁移，不双写，也不在新路径失败后回退到完整 JSON 加载。来源、收藏、历史
和 EPG 设置保留；新 SQLite 缓存按需重新获取。旧 JSON 保留一个回退版本周期，之后只能由精确缓存清理
删除。首次升级且离线时旧 EPG 暂不可显示，这是明确兼容限制；已有新 SQLite 缓存后离线可继续有限查询。

## 资源测量协议 v1

正式资源采样前冻结设备、系统、Release 二进制 SHA、fixture SHA、频道目录、可见需求和操作脚本。
指定设备沿用 9C.3：iMac21,1 / Apple M1 / 16 GB，macOS 14.8.9 (23J631)。设备或协议变化保留旧结果并
完整重跑相关矩阵。

每个规模/格式/场景至少三次独立 Release 进程，报告全部原始数据、最大值和中位数。cold 是新进程、
新 SQLite 缓存，在 EPG 服务初始化完成且未导入前取 baseline；不声称清除了 OS 文件缓存。warm 是同进程
已有 active、有限维护完成后刷新，并在刷新启动前取 baseline。

峰值窗口覆盖网络/暂存、解析、SQLite staging/validate/activate、Repository 查询、UI 有限结果交付、
后台有限维护和任务结束后一秒。RSS/phys_footprint 每 10 ms 采样并在阶段边界补采；磁盘/FD 每 100 ms
及所有权边界补采。settled 在所有已知任务/有限维护返回后 5 秒取点并报告趋势，现阶段不设数值硬阈值。

生产全链路 200K XMLTV 的拟定硬门槛为 RSS 与 phys_footprint 峰值增量分别不超过 48 MiB；50K 到
200K 的三次最大峰值增量之差分别不超过 8 MiB。48 MiB 在实测通过前不得写成现有能力。底层 9C.3 的
32 MiB/8 MiB 及查询 P95 50 ms 门禁继续保留。视频播放采用同源、同操作脚本的 EPG 开关对照，不将
MPV 的绝对 RSS 套用 importer 门槛。

## 阶段与放行

严格按以下顺序推进；前一阶段验收失败不得进入下一阶段：

1. A：保存完整基线；冻结接口、升级语义、状态、deadline 和测量协议；列全生产调用点。
2. B：生产目录与 EPG 服务所有者、有限协议、生命周期、持久化摘要和有限维护。
3. C：Repository 接入 SQLite；Xtream short EPG 有界缓存；刷新、新鲜度、coverage 和错误语义。
4. D：LiveEPGState、实际可见需求、直播卡片、播放器、节目边界和状态展示接入。
5. E：故障、取消、迟到结果、升级、睡眠、关闭和播放独立性专项。
6. F：底层门禁复验、生产资源矩阵与已授权真实来源端到端验收。
7. G：全量回归、文档、完整 Release 打包、签名/解包验证和桌面安装副本验证。

每阶段保存改动清单、命令、原始结果、未覆盖事项和放行结论。真实 TVBox/CatPaw/Xtream 私有样本只有
在用户已授权且能够安全脱敏冻结时测试；缺失样本明确标记未验证，模拟数据不能替代真实生态结论。

G 通过后才运行完整 `package-app.sh` 并替换桌面 App。任何构建、bundle、签名、解包或安装副本验证失败
都不得替换桌面版本。未提交 Git、未创建 Tag、未发布，除非用户另行明确要求。
