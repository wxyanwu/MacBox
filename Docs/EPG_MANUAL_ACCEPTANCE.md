## 可复现本机样本（只用虚构账号）

在仓库根目录执行：

```sh
python3 -B Tools/epg-acceptance-server.py
```

- M3U：添加 URL http://127.0.0.1:18765/live.m3u。
- 无 EPG M3U：http://127.0.0.1:18765/no-epg.m3u。
- Native Xtream：服务器 http://127.0.0.1:18765，用户名 fixture，密码 fixture。
- 空 EPG Provider：同一服务器，用户名 empty，密码 fixture；作为第二个 Provider 添加。
- 第 3 频道无节目；其他节目每分钟换一档，故可在 Live 浏览卡片测试边界。
- 媒体是仓库已有的短 MP4，仅用于目录/可启动播放的 smoke，不是真正连续直播。
  持续播放、真实换台体验和播放器内节目边界必须再用真实可用直播源验证。
- Ctrl-C 停止。要模拟慢 EPG，重启时加 --epg-delay 10。
  要仅让 EPG 失败而保留目录和播放，重启时加 --epg-failure。
  Native 新请求 5 分钟 TTL、空表 15 分钟，已有缓存可能暂不发新请求；
  可换到未请求过的频道/新测试 Provider，或等待过期。
- 此工具只监听 loopback，不记录请求 URL，不需要真实账号，测试结束请停止。
  不提供远程部署，不作为后台服务使用。

## M3U / XMLTV

逐项记录“通过 / 失败 + 复现步骤”，不要只凭页面有节目就全部通过。

1. 当前节目：标题与源数据相符，当前时刻落在 [start, end)。
2. 下一节目：有下一档时显示正确标题和开始时间；无下一档显示 —。
3. 时间/进度：本机显示时区正确；节目中段进度约对应已播比例，不小于 0 或大于 100%。
4. 边界：用每分钟样本等候换档，不点击刷新。当前/下一档自动切换，进度从新档重算。
5. 断网旧缓存：先成功加载，停止样本服务/断网；切回已加载频道和重启候选。
   仍保留覆盖当前时间的旧节目。过期档不能继续冒充当前节目。
6. 刷新失败：服务加 --epg-failure；等待失效后应出现失败/旧缓存提示，
   不清空上一份有效表，也不阻塞目录或播放。
7. 无 EPG：添加 no-epg.m3u，目录正常，播放不依赖 EPG，暂无节目不是播放错误。
8. 时区：样本 XMLTV 为 +0800，显示应转换成本机时区；真实源抽查午夜前后。
   DST 重复小时/UTC 默认已自动测试，不要求修改 Mac 系统时钟来模拟。
9. 旧版缓存升级：有原版 XMLTV 缓存的情况下，首次启动候选时断网，
   原缓存仍可在同一来源中使用；同名另一来源不能串台。

## Native Xtream

1. 目录：分类与频道正常，切到 Live 不要求先拿到所有频道节目。
2. 播放：用真实源确认音画正常；EPG 报错不能变成播放错误。
3. Now / Next：播放频道优先拿节目，标题、开始/结束时间、进度一致。
4. 无 EPG Provider：用 empty 测试账号或真实无 EPG 服务商，仍能浏览和播放。
5. 切台不等待：启用 10 秒 EPG 延迟，在未缓存频道间切换，不能等 EPG 返回才开始播放。
6. 快速连续切台：连续切换至少 10 次，最终显示最后频道的节目；
   先前频道的迟到结果不能覆盖当前频道。
7. 空 EPG：第 3 频道/empty 账号显示无节目，不无限加载，不高频重复请求。
8. Provider 切换：A/B 允许相同 streamID，但节目不能混用；切换时旧 Native 展示立即清除。
9. 账号修改：同一 Provider 修改测试用户名为 empty，旧节目不能残留；
   再改回 fixture，应以新 revision 加载。不要在反馈里粘贴真实 credential。
10. Sleep / Wake：播放中睡眠超过一个节目边界再唤醒，时间/进度立即重算；
    再测试未播放、仅浏览 Live 时睡眠，醒来同样更新。
11. 离线/错误恢复：先加载节目，再只让 EPG 503；旧表保留，恢复服务后后台可刷新。
12. 滚动：同一真实大目录对照原版与候选，连续快速滚动 30 秒，
    观察明显掉帧、CPU 峰值或反复 loading；不要求每个离屏频道都已有节目。
