## 1. 目标和范围

10A 在 9C.4 的有限查询上建立直播节目单。用户可在频道卡片与节目单之间切换，按来源、分组、收藏、频道搜索过滤；浏览缓存覆盖范围，查看节目名称和起止时间，选择“播放频道”。

覆盖范围表示来源提供的数据范围，不承诺每个频道连续覆盖或都有七天节目。未来和过去节目不提供回看、预约、录制或自动播放语义。节目搜索、详情联网补全、手工映射、多 EPG 合并和 Xtream 全量 XMLTV 自动发现均不进入本阶段。

下载、解析、SQLite schema、generation 发布、GC、账号身份和频道匹配策略沿用 9C.4。允许补充有限查询结果的节目身份、错误分类与 Xtream 缓存投影；这些属于消费接口补全，不改变存储和导入语义。

最高约束：Guide 查询永不进入播放器起播、换台和恢复播放的等待链。EPG 不可用仍能播放频道。

## 3. 分层

Core：Guide demand、row、snapshot、capability、预算计费、时间切片、纯布局和焦点算法。

Repository：现有 XMLTV 窗口查询；Xtream 同一缓存的有限行投影。

Guide Coordinator：desired set、执行准入、cursor、有限重试、token 仲裁、有限结果组装。

LiveGuideState：MainActor 上的有界展示与选择状态。

AppKit：NSCollectionView 节目块虚拟化和复用、滚动、命中、键盘、可访问性；SwiftUI 负责工具栏、日期、状态和轻量详情。

AppState 仅提供来源、配置修订、频道目录、播放入口和生命周期事件。滚动偏移、布局缓存和时间线刷新不进入全局 AppState。Guide 与 Now/Next 共享资源刷新所有者，不创建第二个 Repository/SQLite Store。

## 4. 来源能力

按实际能力选择适配器，不按 TVBox/CatPaw 品牌推断能力。

- XMLTV：有合法配置及 active generation 时消费有限窗口；匹配规则保持现有 exact/normalizedUnique/ambiguous/unmatched。
- Xtream：复用现有 XtreamEntry、flight、身份和缓存；增加有限 window projection。缓存最多 16 条不等于服务端保证返回 16 条，也不在本阶段提高请求条数。
- 无 EPG：频道列和“播放频道”仍可使用，展示未配置、已关闭或不支持的真实状态。

Xtream 横向浏览只投影已有短表，不因每个新时间片重复请求。日期导航不能暗示有完整历史/未来表。来源提示为“此来源仅提供近期节目”；窗口之外标记未提供，不能冒充查询已证实的空节目。

Now/Next 和 Guide 对同一 Xtream key 合并请求；取消一个消费者只撤销该消费者交付资格，不取消仍被另一消费者需要的 flight。共享任务的取消、背压和退避按资源身份管理。

## 5. 需求与执行

desired row set <= 48，保存全部目标行及有限状态，不创建 48 个等待 Task。

running <= 4；runnable queue <= 8。队列为空位时，从 desired set 按优先级补齐；每个完成、失败或取消都释放名额并继续补充。没有进入 queue 的目标保持 pending，不被遗忘。稳定需求及正常服务下，48 行最终全部进入终态。

优先级：当前可见的焦点/播放频道、其他可见行、邻近预取行、相邻时间预取。持续分页不能饿死尚未加载第一页的可见行。播放频道不在当前过滤目录内时，由现有 Now/Next 维护，不偷偷插入 Guide。

数据库仍使用现有串行 reader。running=4 是 Coordinator 最大异步操作数，不是新建四个 SQLite reader。Now/Next 使用同一读取基础设施，需要保留执行机会；Guide 不能预先塞满底层队列。

队列描述符也有长度和字节限制；错误只保留有限错误码，不保存完整 NSError、URL 或 payload。

滚动先实时更新视觉，只有跨越频道需求或时间预取边界时更新数据需求。连续像素移动、时间线 tick 不换 demandRevision。需求合并采用短 debounce 并设置最大等待时间，避免持续滚动永远不加载；具体默认值在 A 冻结，建议 debounce 100 ms、最长等待 250 ms。

## 6. 时间与窗口

单时间片为绝对时间长度 12 小时，最多保留两个相邻切片；查询窗口仍不超过 24 小时。日期跳转直接建立目标窗口，不加载途经日期。

Calendar/TimeZone 用于日期导航和标题。23/25 小时民用日期不转换成一次完整“当天”查询；先定位目标日期，再围绕视口查询最多两个 12 小时片。DST 重复时间在必要时显示时区偏移以便区分。

首开围绕当前时间；“回到现在”恢复当前时间，播放频道仍在过滤结果中时定位到该行。普通刷新不改变滚动位置。用户浏览历史后不强制拉回当前时间。

窗口 resize 时保持视口中心或焦点节目的绝对时间锚点。时间缩放有最小/最大值，任何视口都不得要求超过 24 小时。超高窗口通过最小行高保证实际可见行本身不超过 48；预取只使用剩余额度，不让屏幕上出现永久未准入的第 49 行。

coverageStart/End 仅决定可导航的包络范围，不证明每个频道在包络内连续有节目。首个版本不增加全表节目搜索。

## 7. 节目身份与接口补全

当前 EPGProgramme.id 为 channelID + start + title；这不能区分数据库保留的重复记录。当前生产窗口投影丢弃了底层 ordinal。Guide 不能直接以这个 id 驱动 CollectionView 或跨片去重。

增加窗口 item 身份：XMLTV 由 resource/source epoch/generation/ordinal 形成不含凭据的记录身份；Xtream 使用频道缓存版本加条目序号。视图 item 还包含直播频道行身份，允许两个直播频道映射到同一个 XMLTV 频道。

两个切片相交的长节目按记录身份只保留一份逻辑记录；原始重复 programme 的不同 ordinal 则保留。切代后不把旧 ordinal 对应为同一节目；焦点仅以频道及时间锚点做尽力恢复。

query 的 snapshotChanged 目前映射为 invalidRequest。Guide 路径补充明确的换代错误分类，参数错误/伪造 cursor 不触发换代重试。queryBudgetExceeded 与数据库 unavailable 也应保留可审计的区别；不得将后者伪装成空表或正常截断。

这些是 additive projection/error API 改动，保留既有 Now/Next 兼容性，不迁移 schema，不修改 SQL 匹配和分页排序语义。

## 8. 一致性与发布

EPGGuideSnapshot.coherence = xmltv(coherenceToken) 或 perRowToken。

xmltv coherenceToken 是完整 EPGResultToken 的类型化一致性证明，绑定 serviceIncarnation/resourceIdentity/sourceEpoch/dataVersion/demandRevision；不能仅生成一个与这些事实无关的随机 UUID。

Coordinator 首先确认当前资源身份；所有成功行、空查询、分页结果必须匹配同一 token。失败行作为该需求下的有限占位，不携带另一 generation 的内容。结果组装结束后再次核验身份；MainActor 在无 await 的发布点核验需求与已知资源撤销状态，整体替换 snapshot。

数据库可以在校验后继续 activate，因此合同保证的是“已验证版本、整图不混代、撤销后不再接受旧交付”，不声称数据库与 UI 跨 actor 永久同时处于最新代。切代通知或状态核验使旧图变为待更新，重新建立需求。

候选组装中发现冲突：废弃整个候选、cursor 和对应失败集；同一来源/配置的旧图可继续显示。切到另一个来源、禁用来源或切换账号时立即撤下旧图，不能靠 stale 保留跨源内容。

每个需求根自动重试最多一次，即初次尝试加一次重建；重试次数不能因内部生成新 demandRevision 而清零。再次冲突后结束本轮，保留可用旧图并标记更新未完成。连续 activate 事件合并且限频，不借事件无限重启失败循环。新用户需求或退避后的新刷新周期才开启新重试预算。

Xtream 各行独立 token、各行验证与更新；仅 UI 需求身份共享，不伪造跨频道 generation。

## 9. 预算与截断

所有上限同时适用：desired 行 <=48；单频道跨两片去重后 <=256 programme；Guide 全局 <=6144 programme；确定性 DTO 计费 <=8 MiB。任何一个触顶就停止继续准入。

8 MiB 不是 Swift heap。确定性计费 v1 冻结为：Programme 固定 128 bytes；行固定
256 bytes；token 固定 192 bytes；slice 固定 128 bytes；cursor wrapper 固定 256 bytes；
任务描述符固定 160 bytes；失败记录固定 96 bytes。每项再加其实际保存的所有 String UTF-8
字节；数组中的每个逻辑记录已经由相应固定成本计入。相同内容被复制保留时分别计费；只对显式共享的
不可变记录计一次。测试使用同一公开计费函数作为精确 oracle。

Guide 请求分页大小固定为 64 条，单行至多四页达到 256 条。预算覆盖 Guide 持有的旧图、候选、
预取、分页累积、详情引用和已接收结果，不是仅发布后的数组。每个 XMLTV 在途查询在发出前预留
2,162,688 bytes（Store 单页 2 MiB 上限加 64 KiB 投影余量）；Xtream 在途查询按现有单项 64 KiB
上限再加 16 KiB 投影余量，预留 81,920 bytes。预留算入 8 MiB，完成、失败或取消后必须释放。
实际 running 由剩余预算决定，可小于 4；四个并发名额不是必须填满的目标。

优先淘汰非可见预取；优先保可见行及用户当前浏览时间附近内容；“当前时间附近”在用户浏览未来时指当前视口时间锚点。可先查更小子窗口，避免顺序分页把预算全花在不显示的早期节目上。

截断原因明确区分 perRowLimit/globalItemLimit/byteBudget。预算不足不能等待永远无法释放的名额：
先清除非可见预取和无焦点详情引用；仍无法为可见行预留一个查询时，结束旧图保留并进入有限 loading
状态，为当前可见需求释放空间。在预留预算下完成有限候选，允许以截断状态发布，或保留旧图并结束
该轮。不能无限重试，也不能为保留旧图突破预算。新旧图同时保留不是保证满额双份；触顶行为在 B
专项证明能终止且不饿死其他行。

queryBudgetExceeded、busy、超时等是查询失败/退避，不是合法 empty。未读完的分页区域呈现“内容未完全载入”，不能留白暗示没有节目。

排版、CollectionView item、文字测量、图片缓存另设有界容量；屏幕外全部节目不能拥有永久 layout attributes 或 NSView。图片仅请求可见行及少量预取，复用既有 logo 策略，不引入新远程补全。

## 10. 状态

顶层 lifecycle = inactive/loadingInitial/content/empty/unsupported/failed；资源刷新保留旧数据时仍为 content。

content 分解为 snapshot、freshness(fresh/stale)、refreshPhase(idle/loading/backoff)、bounded failures。不能把 refreshing 放进 freshness 后丢失“旧缓存正在刷新”的组合。失败集最多按目标行保存，并计费。

行状态保留 loading/ready/empty/unmatched/ambiguous/unsupported/failed/truncated。截断行可以携带已取得的节目和明确的未完成区域。源级已关闭、未配置、合法空 active、频道未匹配、窗口没有节目和失败必须有不同原因。

empty 仅由成功且完整的查询事实产生；如果所有行都加载失败，顶层是 failed。部分成功以 content 加 failures 表达。窗口加载中不能把缺失行自动标为 empty。

## 11. 界面与渲染

入口为直播页“频道 / 节目单”，使用既有来源、分组、收藏、频道搜索和受保护分组策略。窄窗口时工具栏折叠到菜单，不牺牲播放入口。

NSCollectionView 负责节目块虚拟化与复用；顶部时间轴、左侧频道列可使用 pinned supplementary views 或同步偏移的独立 AppKit view。共享一个滚动坐标事实，固定区仅跟随对应轴，不能形成反馈滚动循环。

顶部时间、左侧频道固定；节目按时间比例显示。时间线仅在可见页面内局部更新。后台、隐藏和睡眠停止显示时钟；恢复按 Date 重算。系统时区变化重建标签和日期导航。

单击节目选择并展示轻量详情；双击节目或在网格焦点内按 Return 执行“播放频道”；搜索输入等其他控件不被抢键。详情只有已有标题、频道、起止时间和状态，不伪造描述/海报。

上下移动按同一时间锚点寻找相邻频道节目，左右移动同频道相邻节目。在未加载边界先请求有限窗口，使用频道+时间锚点保持焦点，不按旧数组索引命中。发布、排序或来源改变时再次验证选择身份再播放。

空档保留；裁剪只影响绘制不修改时间。重叠按现有 Now 语义保持一致：start DESC、ordinal DESC 决定主节目，不任意选第一条。最多两条视觉 lane；更多重叠用有界列表展示已加载候选并标明可能截断。行高固定或有封顶，不能随重叠数量无限扩张。

极短节目的命中区不得吞掉相邻正常节目；使用最近中心/明确的候选选择解决冲突。可访问性元素仅为可见/焦点附近创建，VoiceOver 可逐步滚动浏览，不能为整个节目库预生成元素。

G：全量回归、文档和打包。运行标准 package-app.sh 或调用它的 local acceptance 流程；核验 bundle/SBOM/签名/敏感信息/DMG/ZIP/安装副本，通过后替换非隐藏桌面 Release App。中途失败保留旧桌面版本。记录签名/公证实际状态，不默认发布线上 Release。

每一步都输出实际命令、原始结果、失败修复及剩余缺项。未通过则停留本步；缺证不能写成 PASS。

## 13. 性能协议与拟定门槛

测试前冻结设备、系统、Release binary/fixture hash、源/频道目录、窗口尺寸、缩放、显示器倍率和刷新率、滚动/日期跳转脚本。每场景至少三次独立进程，报告每轮、最大值、中位数、样本量和 percentile 算法；不在看到结果后改口径。

正常 Store Window Query（reader 实际开始到有限结果构造结束，不含外部排队）每轮 P95 <=10 ms；正常样本单次 <=50 ms 作严重回退门槛；Repository 排队、身份复核等端到端延迟另记。故障/超预算输入单独衡量有界退出，不混入正常时延分布，也不能以快速失败满足成功查询门槛。

同 fixture 的 9C.4/10A 配对结果同时报告比例和绝对差；9C.2 裸 Store 与 9C.4 Repository P95 不能直接混比。即便未超过 10 ms，出现多倍退化也必须定位解释。

缓存已准备、窗口稳定的场景：全部实际可见行的初始结果或明确终态完成且真实绘制，P95 <=500 ms。另记第一行显示时间；不以 skeleton 或第一行代替全屏完成。

Guide 场景 RSS 峰值增量拟定 <=32 MiB。baseline 为同一进程、同一已加载目录及 active cache、Guide 尚未创建时；峰值覆盖网格创建、首次绘制、双轴滚动、日期跳转、切代旧新图并存、退出后 1 s；RSS/footprint 每 10 ms 采样并补阶段点，settled 在任务退出后 5 s 记录。phys_footprint 同报；不把 DTO 8 MiB 等同 RSS。

滚动渲染帧间隔 P95 拟定 <=25 ms，目标测试屏幕 60 Hz；掉帧率和可归因于 Guide 的主线程 >100 ms 停顿单独记录，后者目标为 0。必须采集实际 AppKit 刷新/呈现证据及主线程跟踪，不用普通 Timer 回调时间冒充 FPS。

原有 9C.x 资源/查询门禁继续成立，10A 的 Guide 增量不能替代 importer 门槛；同时导入、浏览和播放的场景单独记录全进程峰值，不机械相加 32 与 48 MiB 宣称能力。

矩阵：100/500/1000 频道；10K/50K/100K/200K programme；稀疏、正常、密集、重复、重叠；普通/超长标题、跨午夜、DST；窄/宽/全屏/Retina；plain/gzip 导入后查询；cold Guide/warm Guide、刷新和持续导航。

本地确定性媒体至少 30 分钟播放对照：EPG 开/关、Guide 开/关、刷新及故障期间记录首帧/换台分布、掉帧和播放失败；网络波动与实现影响分开报告。

公开真实 XMLTV 冻结样本重放与实时网络测试分开记录。TVBox/CatPaw/Xtream 私有源仅在已授权且样本可用时验收。缺失私有覆盖时可以交付注明限制的本地测试包，不能声称全部生态真实源验收通过。

## 14. 完成定义

基线可恢复，新开发独立分支；数据与纯 UI 先各自通过，再接线。最终应证明：所有目标行可达、不混代、不串源、不抢播放、预算包含过渡期且不无限增长、短表/失败/空表语义准确、布局和焦点稳定、实测性能满足预先冻结门槛。

实现与自动验收通过、真实 UI/资源通过、真实私有来源覆盖分别记结论。最终报告逐项列证据与未验证范围，不用一个总 PASS 覆盖缺失的人工或真实来源证据。
